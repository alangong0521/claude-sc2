# 流派方案 · 修地堡（Cannon Rush）

> 优先级 B 级（娱乐效果 S 级）· 预计改动量：**大**——这不是一个流派配置，是独立 feature
> 社区出处：神族第一招牌大招，每个神族玩家的必修课。

## 流派定位

农民溜进对面基地附近，forge + 光子炮（PHOTONCANNON）+ 护盾电池（SHIELDBATTERY）
修到对面脸上。对本项目的观赏价值拉满（司令看修地堡是节目效果天花板），
但**和现有体系的接缝完全不同**，先认清这一点再排期：

- 现有 `build` 杠杆只在**自家主基地**摆建筑（选农民/选位置全归 ares 默认逻辑）。
- 修地堡需要在**敌方基地**摆建筑 + 农民护送 + 炮位互相覆盖的位置学——
  这三样现有代码一个都没有，是新逻辑而不是新配置。

## 改动清单（按依赖排序）

1. **进攻性摆点求解器（大头）**：给定敌方基地位置，在矿区/主基地射程边缘选炮位，
   要求炮与炮互相覆盖、电池覆盖炮。输入敌基地坐标（`focused_enemy_start()` 已有），
   输出一串建筑队列（forge → 第一门炮 → 电池 → 后续炮前移）。位置学是全新代码，
   建议落在 `bot/offensive_placement.py`，纯逻辑可单测。
2. **农民护送/执行逻辑**：派 1-2 个农民去敌基地（可复用 scout 的派遣/role 机制），
   按求解器队列依次造；农民被攻击时撤退/绕位/必要时拉第二个农民。
   状态机：出发 → 起 forge → 起炮 → 电池 → 前压/补炮 → 完成或放弃。
3. **杠杆扩展**：`build` 目前只认结构名，位置语义固定自家。需要扩展成
   `build=photoncannon at=enemy_natural` 之类的语义（或新开一个 `rush=cannon` 杠杆），
   动 `steer_vocab.FIELDS` + 校验 + SKILL.md 词表重生成。
4. **反制识别**：对面农民围殴/出兵拆炮时，参谋长要有「放弃」选项（`clear` 回默认）。
5. **build_meta.md**：新增 `CannonRush` 档案段——写明这是大招、失败即大亏、
   对什么 AI 有效（对 Mineral-line 不设防的 AI 效果拔群）。

## 验证

- 纯逻辑单测：摆点求解器（给定基地坐标 → 炮位队列合法性：互相覆盖、在建造范围内）。
- 实机 `REALTIME=True` 观赏局为主：看农民走位、炮位、AI 反应（AI 会不会拉农民围殴）。
- 胜率不作为首要验收标准（这是大招）。

## 风险

- 工作量为所有方案之最（摆点 + 护送状态机 + 杠杆扩展三件套），建议在其他流派都落地后做。
- AI 对修地堡的反应因内置 AI 实现而异，可能一招鲜也可能完全无效——先跑一局探虚实再
  决定是否投入完整实现（**建议先用最小原型探路**：手动把农民拉过去 + `build` 摆一门炮，
  看 AI 反应）。
